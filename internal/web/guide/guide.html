Station settings (Admin → Station)

Callsign (graywolf)

The Amateur Operator's callsign, used for all messaging at this station. It is graywolf's station callsign, so changing it changes graywolf for everything, not just the race.

Race settings

Role
Checkpoint or HQ. It can only change before the race starts (or after a reset).
Race name
Shown in headers and exports.
Station name
What people call this station on the voice net, e.g. "Ridge Aid #3". Up to 25 characters. Shown on the keypad and panel; never sent on air.
Checkpoint code (checkpoint)
Sent in every radio report, e.g. AS5. A–Z and 0–9, up to 6. It must match an entry in HQ's checkpoint list. Don't change it during a race.
HQ callsign (checkpoint)
HQ's station callsign (optional -SSID). Reports go there, and only HQ can ask this station to resend. It must not be this station's own callsign.
Local codes (HQ)
Codes HQ logs on its own keypad, e.g. START,FIN. Not sent on air.

Messaging settings

Radio tunables. The defaults suit most races; change them only after a link check shows a reason to.

Digipeater path
Blank = direct (the default). See paths below.
graywolf channel
0 = graywolf's default transmit channel.
Heartbeat every (s)
How often an idle checkpoint tells HQ it is alive. Default 300, range 60–3600.
Batch after (s)
How long to collect bibs before sending a report. Default 20, range 5–300.
Batches in flight
Reports sent before waiting for HQ's acknowledgements. Default 4, range 1–8.
Max message length
Characters per radio message. Default 67, range 67–200; over 67 needs graywolf long messages.
Gap grace (s, HQ)
How long HQ waits on a missing report before asking for it again. Default 90, range 30–900.

Radio and graywolf

  • Every node needs its own callsign-SSID, e.g. HQ KD2DCM-3 and a checkpoint KD2DCM-4. graywolf ignores messages from its own callsign (and -0 counts as no SSID), so two nodes sharing one never hear each other. Different SSIDs of one callsign are separate stations.
  • Frequency: APRS in the US is 144.390 MHz. Heavy race traffic there competes with the national APRS network; many events use a coordinated packet simplex frequency instead (e.g. 145.010–145.090). Agree on it with HQ and your frequency coordinator.
  • Digipeater path: use the shortest path that reaches HQ. Direct (blank) when HQ is in range; otherwise one named digipeater, or WIDE1-1. Each hop adds a transmission and delay.
  • Retries: during a race, checkin-board turns off graywolf's own message retries for race contacts and retries itself. Messages typed in graywolf's Messages page to those stations then go out once, with no retry. They are restored after the race.

Pi Zero nodes

A Raspberry Pi Zero W (single core) needs two changes, or receive and transmit fail:

  1. A fixed graywolf build: graywolf with cpal 0.18 (a silent carrier on transmit otherwise) and the ARMv6 audio-buffer patch, built with checkin-board's deploy/graywolf-armv6/build.sh. Install checkin-board with install.sh --no-graywolf so a release never replaces it.
  2. 24 kHz audio in graywolf for the AIOC (input and output). At 48 kHz the Zero can't keep up and receives nothing.

Setting graywolf's audio to 24 kHz

graywolf's web UI can't do this: Audio Devices → Edit only offers 8000, 16000, 44100 and 48000 Hz. graywolf's API accepts 24000, so set it from a shell on the node (SSH), with the graywolf web login:

GW=http://127.0.0.1:8080
read -p 'graywolf user: ' U; read -s -p 'graywolf password: ' P; echo
J=$(mktemp)
printf '{"username":"%s","password":"%s"}' "$U" "$P" |
  curl -s -c "$J" -H 'Content-Type: application/json' --data-binary @- \
       -o /dev/null -w 'login: %{http_code}\n' "$GW/api/auth/login"
# Every AIOC device (input and output) -> 24000 Hz; other fields unchanged.
for id in $(curl -s -b "$J" "$GW/api/audio-devices" | python3 -c '
import sys, json
for d in json.load(sys.stdin):
    if "AllInOneCable" in d["device_path"]: print(d["id"])'); do
  curl -s -b "$J" "$GW/api/audio-devices/$id" | python3 -c '
import sys, json
d = json.load(sys.stdin)
keep = ("name", "direction", "source_type", "device_path", "channels", "format", "gain_db")
out = {k: d[k] for k in keep}
out["sample_rate"] = 24000
print(json.dumps(out))' |
  curl -s -b "$J" -X PUT -H 'Content-Type: application/json' --data-binary @- \
       -o /dev/null -w "device $id: %{http_code}\n" "$GW/api/audio-devices/$id"
done
rm -f "$J"

Expect login: 200 and device N: 200 for the input and the output. graywolf applies the change at once; no restart is needed. Check:

  • graywolf → Audio Devices shows "Sample Rate 24000 Hz" for both AIOC devices;
  • sudo journalctl -u graywolf -n 50 | grep "buffer 2048" shows "input buffer 2048 frames/period";
  • grep -E 'rate|period_size' /proc/asound/card0/pcm0c/sub0/hw_params shows rate: 24000 and period_size: 2048.

Don't open Edit on these devices in graywolf's UI afterwards: 24000 isn't in its list, so saving the dialog can reset the rate. If the devices are edited or recreated, run the script again. On a faster Pi, change 24000 to 48000 and run it again to go back.

Testing a link

  • Link check (Admin → Link check): run it at every station's location before the race. A few short test messages confirm the link to HQ (or, at HQ, to a checkpoint).
  • Listen with a third radio tuned to the frequency, squelch open, while a node transmits. One clean burst of packet tones is good. An open carrier with no tones means no audio reaches the radio (graywolf build or audio setup); choppy or cut-off tones mean audio problems on that node; silence means the radio isn't keying (PTT).
  • Check acknowledgements: a message is only delivered once the other station acknowledges it. In graywolf's Messages page an acknowledged message shows as acked.
