Station settings (Admin → Station)

Callsign (graywolf, or the radio)

The Amateur Operator's callsign, used for all messaging at this station. It is graywolf's station callsign, so changing it changes graywolf for everything, not just the race. On a UV-K5 it is the radio's own callsign-SSID, saved in the radio.

Radio (Radio type, Check radio)

Radio type is the kind of radio this node sends through: a radio on an AIOC cable (graywolf), or a UV-K5 V3 / UV-K1 on USB-C. Changing it restarts the app for about 10 seconds; it can be done mid-race when a radio is swapped (see Radio types). Check radio checks the chosen radio without transmitting.

Race settings

Role
Checkpoint or HQ. It can only change before the race starts (or after a reset).
Race name
Shown in headers and exports.
Station name
What people call this station on the voice net, e.g. "Ridge Aid #3". Up to 25 characters. Shown on the keypad and panel; never sent on air.
Checkpoint code (checkpoint)
Sent in every radio report, e.g. AS5. A–Z and 0–9, up to 6. It must match an entry in HQ's checkpoint list. Don't change it during a race.
HQ callsign (checkpoint)
HQ's station callsign (optional -SSID). Reports go there, and only HQ can ask this station to resend. It must not be this station's own callsign.
Local codes (HQ)
Codes HQ logs on its own keypad, e.g. START,FIN. Not sent on air.

All of these can be loaded from a race config file (Race → Race config): HQ exports its setup, each node loads it and picks its station, previews the changes, and loads it before the race. A loaded file only sets values; everything stays editable here.

How long HQ waits on a missing report before asking for it again. Default 90, range 30–900.

Radio and graywolf

  • Every node needs its own callsign-SSID, e.g. HQ KD2DCM-3 and a checkpoint KD2DCM-4. graywolf ignores messages from its own callsign (and -0 counts as no SSID), so two nodes sharing one never hear each other. Different SSIDs of one callsign are separate stations.
  • Frequency: APRS in the US is 144.390 MHz. Heavy race traffic there competes with the national APRS network; many events use a coordinated packet simplex frequency instead (e.g. 145.010–145.090). Agree on it with HQ and your frequency coordinator.
  • Digipeater path: use the shortest path that reaches HQ. Direct (blank) when HQ is in range; otherwise one named digipeater, or WIDE1-1. Each hop adds a transmission and delay.
  • Retries: during a race, checkin-board turns off graywolf's own message retries for race contacts and retries itself. Messages typed in graywolf's Messages page to those stations then go out once, with no retry. They are restored after the race.

Radio types (AIOC, UV-K5/UV-K1)

Every node can send through either kind of radio. Choose it on Station → Radio → Radio type:

  • Radio with an AIOC cable (graywolf): any 2 m radio on an AIOC (or other sound-card) cable; graywolf on this node is the modem. See Radio and graywolf.
  • UV-K5 V3 / UV-K1 on USB-C (APRS firmware): the radio does the packet work itself, so any Pi has CPU to spare. Use it for checkpoints only; keep HQ on graywolf: the current UV-K5 firmware doesn't acknowledge long messages, so a UV-K5 HQ never confirms a checkpoint's reports.

Nodes with either radio work together in one race on one frequency. A type that can't be used on this node is marked "not available", with the reason.

Swapping a radio, also mid-race

  1. Connect the new radio and set it up (below for a UV-K5; graywolf's audio and PTT for an AIOC radio).
  2. Choose its type under Radio type and press Change radio type, then confirm.
  3. The app restarts with the new radio in about 10 seconds; this page reloads by itself. A bib logged meanwhile shows NOT confirmed: tap LOG again (it is never logged twice).
  4. Run Check radio. If the callsign is wrong, set it with Callsign at the top of this page.
  5. Unplug or switch off the old radio: graywolf keeps running, and would still digipeat or beacon if set to.

Nothing is lost: entries are kept, and reports HQ hasn't acknowledged go out again through the new radio (HQ ignores repeats).

Before the race, on a UV-K5

  • Firmware: the APRS firmware with protocol revision 1 or later (message queue, line numbers, SENT/DROP reports). An older one is refused: Check radio says "firmware too old: reflash".
  • Callsign-SSID: this station's own, not the placeholder N0CALL. Set it on the Station page (Callsign) or in the radio's menu. A radio with N0CALL transmits nothing.
  • APRS on, and the race frequency set on the radio's main VFO, in FM. checkin-board reads the frequency but doesn't change it.
  • Path (radio menu): Direct when HQ is in range, otherwise WIDE1-1. The default WIDE1-1,WIDE2-1 doubles the airtime of every message on a local race.
  • Battery charged: a low battery stops transmitting.

What to expect with a UV-K5

  • Check radio shows: the connection and firmware, callsign, whether the radio would transmit now (and if not, why: no callsign, APRS off, out of band, not FM, battery, busy), frequency, battery voltage, packets decoded and damaged, and the message queue.
  • The radio sends at most one packet every 5 s (acks first) and holds 4 messages. A busy checkpoint's reports queue and go out in turn: about 30-50 bibs a minute on a clean link, fewer when acks are lost. Nothing is lost.
  • "Radio not connected" (keypad, panel "radio DOWN"): the radio is unplugged, off, or another program has its port. Reports are kept and sent when it's back. Check the USB-C cable (it must carry data, not only charge), switch the radio on, and wait a few seconds.
  • A message the radio gives up on (busy channel for a minute, low battery) is sent again by the checkpoint, as with any message HQ hasn't acknowledged.
  • The link check works the same, without signal levels.
  • graywolf-only parts (graywolf retries, TX timing, digipeater, audio) don't apply and are hidden. A race config file sets only the callsign on the radio.

Pi Zero nodes

A Raspberry Pi Zero W (single core) needs two changes, or receive and transmit fail:

  1. A fixed graywolf build: graywolf with cpal 0.18 (a silent carrier on transmit otherwise) and the ARMv6 audio-buffer patch, built with checkin-board's deploy/graywolf-armv6/build.sh. Install it with install.sh --graywolf-deb FILE.deb (it replaces an installed graywolf), and later checkin-board upgrades with plain install.sh keep it (an installed graywolf is never replaced without --graywolf-deb). On a Pi Zero the installer warns when graywolf lacks these fixes.
  2. 24 kHz audio in graywolf for the AIOC (input and output). At 48 kHz the Zero can't keep up and receives nothing.

Setting graywolf's audio to 24 kHz

graywolf's web UI can't do this: Audio Devices → Edit only offers 8000, 16000, 44100 and 48000 Hz. graywolf's API accepts 24000, so set it from a shell on the node (SSH), with the graywolf web login:

GW=http://127.0.0.1:8080
read -p 'graywolf user: ' U; read -s -p 'graywolf password: ' P; echo
J=$(mktemp)
printf '{"username":"%s","password":"%s"}' "$U" "$P" |
  curl -s -c "$J" -H 'Content-Type: application/json' --data-binary @- \
       -o /dev/null -w 'login: %{http_code}\n' "$GW/api/auth/login"
# Every AIOC device (input and output) -> 24000 Hz; other fields unchanged.
for id in $(curl -s -b "$J" "$GW/api/audio-devices" | python3 -c '
import sys, json
for d in json.load(sys.stdin):
    if "AllInOneCable" in d["device_path"]: print(d["id"])'); do
  curl -s -b "$J" "$GW/api/audio-devices/$id" | python3 -c '
import sys, json
d = json.load(sys.stdin)
keep = ("name", "direction", "source_type", "device_path", "channels", "format", "gain_db")
out = {k: d[k] for k in keep}
out["sample_rate"] = 24000
print(json.dumps(out))' |
  curl -s -b "$J" -X PUT -H 'Content-Type: application/json' --data-binary @- \
       -o /dev/null -w "device $id: %{http_code}\n" "$GW/api/audio-devices/$id"
done
rm -f "$J"

Expect login: 200 and device N: 200 for the input and the output. graywolf applies the change at once; no restart is needed. Check:

  • graywolf → Audio Devices shows "Sample Rate 24000 Hz" for both AIOC devices;
  • sudo journalctl -u graywolf -n 50 | grep "buffer 2048" shows "input buffer 2048 frames/period";
  • grep -E 'rate|period_size' /proc/asound/card0/pcm0c/sub0/hw_params shows rate: 24000 and period_size: 2048.

Don't open Edit on these devices in graywolf's UI afterwards: 24000 isn't in its list, so saving the dialog can reset the rate. If the devices are edited or recreated, run the script again. On a faster Pi, change 24000 to 48000 and run it again to go back.

Testing a link

  • Radio check (Station → Radio → Check radio): checks graywolf's build, channel, audio devices, push-to-talk, sample rate, receive level, packets decoded, and whether graywolf's modem keeps up with its audio. Nothing is transmitted. The Race page shows its summary before Start. It also checks that the radio cable's sound card is actually plugged in: graywolf keeps listing a cable that has dropped off USB.
  • "Radio not connected" with a UV-K5: see that section.
  • "Radio cable missing" (keypad, panel, graywolf card, Check radio): the AIOC is unplugged or dropped off USB, so nothing is sent or received even though graywolf looks fine. A checkpoint holds its reports meanwhile (entries are kept and batched, no retries are spent) and sends them as soon as the cable is back. Replug it. On a Pi Zero the USB port can stay stuck after a drop, and only a reboot brings the cable back. A cable that drops every time the radio transmits is faulty or picking up RF: try another cable, a ferrite, or the antenna further from the Pi. Watch that radio: it can stay keyed after the drop.
  • Node panel: shows "modem keeping up" (or BEHIND) and the CPU use over 5 minutes; above 80% it adds a warning line. A modem that falls behind drops received audio without any error.
  • Link check (Admin → Link check): run it at every station's location before the race. A few short test messages confirm the link to HQ (or, at HQ, to a checkpoint).
  • Listen with a third radio tuned to the frequency, squelch open, while a node transmits. One clean burst of packet tones is good. An open carrier with no tones means no audio reaches the radio (graywolf build or audio setup); choppy or cut-off tones mean audio problems on that node; silence means the radio isn't keying (PTT).
  • Event page: course notes, frequencies and contacts for volunteers (keypad → Event info), written on Station → Event page or loaded from the race config.
  • Check acknowledgements: a message is only delivered once the other station acknowledges it. In graywolf's Messages page an acknowledged message shows as acked.
